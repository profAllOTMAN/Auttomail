Old vs New Design

Key differences between the legacy Automai Watcher UI and the new design system

palette Global Design Changes

Aspect close Old Design check New Design
Framework Server-rendered HTML, jQuery-based interactions Angular 21 SSR with signals, standalone components, OnPush change detection
Styling Bootstrap-based with inline styles, no design tokens Tailwind CSS v4 with custom theme tokens (--color-primary: #335A85)
Typography System fonts, inconsistent sizes Inter font family (300-700), standardized scale from 10px to 24px
Icons Mixed icon sets (Font Awesome, custom SVGs) Unified Material Symbols Outlined from Google CDN
Colors Dark navy (#1a2332) header, muted grays, no semantic system Brand primary (#335A85), semantic colors (success/warning/danger), full slate scale
Layout Fixed-width containers, float-based layout Responsive flex/grid layout, max-w-7xl container, mobile-friendly
Navigation Traditional horizontal tabs with underline active state Pill-style rounded tabs with filled active state, icon support

dashboard Dashboard

The main overview screen with system KPIs and process status.

close Old Design
• Simple filter bar with severity badges (Success, Failure, Critical, Warning, Info, Unknown)
• Sort dropdown and time interval filter only
• Empty state: plain text "no process monitor data available"
• No KPI cards, no real-time status overview
• No notification center or timeline feed
check New Design
• KPI cards showing Processes (Active/Inactive), Watchers (Active/Inactive), Bot Manager status
• Timeline feed with latest updates + notification alerts
• Process drill-down: click a process to see assigned watchers
• Each watcher expands to show scenario, sub-processes, transactions with KPIs
• Inline trend charts, success/fail counts, response time per watcher

monitoring Process Monitor List

The table view listing all process monitors with actions.

close Old Design
• Standard HTML table with columns: Actions, ID, Process monitor, Project, Schedule name, Description, rWatchers
• Action icons: play/stop/delete/clipboard as small icon buttons
• rWatcher assignments shown as blue link pills
• Simple pagination (items per page dropdown, basic page nav)
• "Add process monitor" button with green circle icon
check New Design
• Card-based list with status dot indicators and progress bars
• Inline KPIs per monitor: success rate ring, resources, status badge
• Quick actions: Run Now (green), Edit, Delete with hover states
• Slide-in drawer for creating/editing (not page navigation)
• Filter KPI cards at top: total processes, active/inactive counts, watcher counts

edit_note Process Monitor Detail / Edit

The form for creating or editing a process monitor with its 3 sections.

close Old Design
• Full-page layout with 3 numbered green-bordered sections
• Section 1: Name, Project dropdown, Process dropdown, Schedule dropdown, Maintenance calendar, Description
• Section 2: rWatcher Distribution — dropdown for type + selected watcher chips with blue remove pills
• Section 3: Events table — Process monitor item + "+ New event" button, columns: Raise, When, Do
• Top bar has "Process monitors" breadcrumb + "Publish" button (blue)
check New Design
• Slide-in drawer (right side panel) instead of full-page navigation
• Same 3-section concept but within drawer: Info, Watchers, Events
• Rounded inputs with focus rings, consistent spacing tokens
• Event popup: "Set threshold and event" modal with monitoring item, conditions, action type
• Save/Cancel buttons with primary/secondary styling, no full-page reload

desktop_windows rWatchers Management

The rWatchers list page and the "Add new rWatcher" form.

close Old Design
• Tabbed view: rWatchers | BotManagers tabs at top
• Table with checkbox column, icons, rWatcher name (blue link), Username
• Action buttons: Add new, Stop, Start rWatchers
• "Add new rWatcher" opens as right-side panel overlay
• Form fields: BotManager dropdown, username/password/domain inputs, alias, description, RDP parameters (resolution, color depth, IP, timeout)
check New Design
• Card-based grid layout with status dot, alias, IP, bot manager per card
• Live status toggle switch (online/offline) per watcher
• KPI stats: trend chart, checks count, success/fail, response time
• Slide-in drawer for "Add new rWatcher" with same fields, modern inputs
• Screen preview placeholder for live watcher view

notifications_active Event / Threshold Setup

The "Set threshold and event" modal for configuring process monitor alerts.

close Old Design
• Modal dialog with "Set threshold and event" title
• Select monitoring item (dropdown)
• Checkboxes: "Continuously Notify", "Notify when event finished"
• Condition builder: "Response time" + "is greater than" + threshold value
• Where + Event level dropdowns, Email action with recipient field
• Cancel/Save buttons, basic modal styling
check New Design
• Same field structure preserved (familiar to existing users)
• Modernized with rounded inputs, focus rings, consistent spacing
• Color-coded sections: blue for "Select monitoring item", amber for "When", emerald for "Do"
• Action type expanded: Email, Slack, Webhook, SMS options
• Primary/secondary button styling with shadow and hover states

touch_app Key Interaction Changes

open_in_new Navigation Model

Old: Full-page navigations between list and detail views. New: Tab-based SPA with slide-in drawers for all CRUD — no page reloads.

view_in_ar Drill-Down Pattern

Old: Separate Scenario and Watchers tabs in process detail. New: Watcher-first list — click a watcher to expand and see its scenario, sub-processes, and transactions inline.

smart_toy Guided Onboarding

Old: Help page with links to docs. New: Step-by-step wizard (/help/new) and AI chat agent (/help/new3) for guided process setup with inline validation.

notifications Status Feedback

Old: Static status text in table cells. New: Live status dots, toggle switches, trend sparklines, animated typing indicators, and semantic color badges throughout.
